# 틱(1TICK) 뷰 — Dashboard · Tokens · Timeout 공용

**파일**
- 집계: `src/lib/tickStats.ts`(LLM 소스 + `rollupTick`) · `src/lib/bizTickStats.ts`(BIZ 소스)
- 라우트: `src/app/api/tokens/tick/route.ts` · `src/app/api/stats/tick/route.ts`
- 화면: `src/components/tick/` — `TickProvider` `TickToolbar` `ViewToggle` `rangeSync`
  `TickMonitor` `TickMonitorChart`
- 스타일: `src/styles/tick.css`

## 왜 있나

사내 LLM 제약이 **TPM/RPM(분당 토큰·호출)** 이라 초과 여부를 화면에서 봐야 하는데 기존 추이는
5분/1시간/1일 격자라 분당 판정이 불가능했다.

**정각 분 버킷은 판정 기준이 못 된다.** 제약은 "임의의 연속 60초" 기준이라 12:01:13~12:02:12 에
몰린 버스트는 정각 격자에선 두 칸으로 쪼개져 어느 칸도 한도를 안 넘는 것처럼 보인다.
그래서 **초 단위 SQL 집계 위에서 슬라이딩 60초 윈도우의 최대값**을 구한다. 윈도우 시작을 "값이 있던
초" 로만 잡아도 실수 t 전체의 최대와 같으므로(합은 구간별 상수, 어떤 시작점의 창이든 그 안 첫
이벤트 시각에서 시작하는 창이 같은 이벤트를 모두 포함) **근사가 아니라 정확한 최대**다.

**롤업은 순수 함수 `rollupTick()` 하나다** — LLM 소스와 BIZ 소스가 같이 쓴다. 슬라이딩 60초의
정의가 소스마다 갈리면 같은 사건에서 다른 수치가 나온다. 경계 조건(정확히 60초 간격은 창 밖,
빈 입력, 같은 초 다건) 검증도 여기 하나로 끝난다.

## 지표는 화면마다 다르고 서버는 이름을 모른다

서버는 이름 없는 **A/B 두 슬롯**(`TickMinute.rollA`/`rollB`)만 채우고, "A 가 무엇인가"(라벨·단위·한도)는
화면이 `TickMetricDef` 로 정한다. 한도는 프로필과 `config.yml` 을 병합해 `/api/agents` 가 만드는
값이라 서버 집계가 알 수 없기 때문이다 — 그 병합을 tick 집계에 복제하지 않는다.

| 화면 | A | B | 한도 | 소스 | 라우트 |
|---|---|---|---|---|---|
| `/tokens` | TPM(토큰) | RPM(호출) | `agents[].tpmLimit/rpmLimit` | `TRX_TOKEN_DET` | `/api/tokens/tick?view=usage` |
| `/timeouts` | 타임아웃/분 | 실패/분 | 없음(0) | `TRX_TOKEN_DET` | `/api/tokens/tick?view=failure` |
| `/dashboard` | 요청/분 | 실패/분 | 없음(0) | `BIZ` 진입 레이어 | `/api/stats/tick` |

- **Timeout 에 TPM/RPM 을 복제하지 않는다** — 숫자가 Tokens 탭과 글자 하나까지 같아져 화면이
  있을 이유가 없어진다. 같은 테이블에서 `SQL_ERR_PRED`/`SQL_TIMEOUT_PRED` 로 세어 다른 지표를 만든다
- `STAT_CD`/`ERR_CTN` 컬럼이 없으면 `statusAvailable=false` 로 내려 화면이 "측정 불가" 로 밝힌다
  (0 건으로 보이면 "문제 없음" 으로 오독된다). 반대로 **usage 뷰에서는 이 필드를 안 내린다**
- **BIZ 집계는 진입 레이어(`LAYER_ORDER[0]`) 하나만 읽는다.** 사용자 요청 1건 = 진입 레이어 수신
  1건이라 "분당 몇 건" 은 여기서만 정의된다. 하위 레이어를 같이 세면 멀티콜 때문에 부풀어 오른다.
  실패 판정은 화면 나머지와 같은 규칙이다(`ERR_CD` 또는 TEMP 액션 실패 문구 — 여기만 `ERR_CD` 로
  좁히면 대시보드 KPI 와 틱 뷰의 실패 수가 갈린다)
- BIZ 틱에는 `ACTION_TYP`/`FAC_ID` 가 **담기지 않는다**(다른 레이어가 기록하는 값이라 진입 레이어
  행에는 없다). 그래서 대시보드의 ACTION_TYP 셀렉트는 틱 뷰에서 감춘다
- 라우트가 `/api/traces/tick` 이 **아닌** 이유: 그쪽엔 `[traceId]` 동적 세그먼트가 있어 "tick" 이라는
  이름의 트레이스와 경로가 겹친다
- `/api/tokens/tick` 의 **모르는 `view` 는 400 이다** — 조용히 기본으로 떨구면 실패 수를 사용량으로
  읽어 정반대로 오독된다

## 툴바 — `집계 | ● 틱`

- **워딩은 증권 차트 탭(`틱 · 1분 · 일 · 주 · 월`)에서 왔다.** "실시간" 은 아니다 — 이 뷰는 직접
  설정으로 과거 구간도 보고 자동 갱신도 기본이 꺼져 있다. 실제로 갈리는 건 **집계 단위**다
- **진입은 머리말 우상단의 `ViewToggle`** — 제목과 같은 줄(`.dash-head-row`), 조회 줄(`.dash-filter`) 밖.
  기간 프리셋 줄 안에 두면 "기간을 고른 줄 알았는데 화면이 바뀐다" 가 되고, 조회 줄 안에 두면 폭이
  좁을 때 이 토글만 윗줄로 튀어 줄이 깨진다. 세 화면의 머리말은 `.dash-header.stacked` 로 두 줄이다
  (1줄 = 제목 + 토글, 2줄 = 조회 조건 전폭). **토글을 조회 줄로 되돌리지 말 것**
- 버튼 두 개가 아니라 thumb 이 미끄러지는 스위치다(`.view-toggle-thumb`). 칸은 `inline-grid` +
  `grid-auto-columns: 1fr` 로 강제 균등이라 글자 수와 무관하게 thumb 이 정확히 반 칸을 덮는다
- **기간 프리셋 줄 자리는 뷰에 따라 통째로 교체된다** — 틱이면 `TickPresets`(창 길이 + 직접 설정).
  두 줄을 같이 띄우면 "기간을 골랐는데 왜 안 바뀌지" 가 생긴다
- 토글해도 화면이 흔들리지 않게: ① 교체되는 자리를 `.preset-slot` 으로 감싸 **넓은 쪽(틱 8개) 폭을
  미리 확보** ② 동작 버튼은 두 보기가 같은 자리를 쓴다. 그래서 툴바가 `TickPresets`(프리셋 자리)와
  `TickActions`(`조회` 버튼 자리 — 자동 갱신 + 새로고침) 두 조각이다. **한 덩어리로 합치지 말 것**
- **조회 구간은 토글할 때 서로 물려준다**(`rangeSync.ts`, 순수 함수). 집계→틱은 그 길이 이하로 가장
  큰 창(6H 이상은 전부 180분), 틱→집계는 그 창을 덮는 가장 짧은 프리셋. 직접 설정은 **24시간
  이하일 때만** 그대로 넘긴다(더 길면 서버가 잘라 토글 한 번에 경고 배너부터 보게 된다).
  억지로 더 맞추려고 집계에 '5분' 을, 틱에 '7일' 을 넣지 말 것 — **딱 안 맞는 게 의도**다
- `● 틱` 의 점은 자동 갱신이 도는 동안에만 깜빡인다(`.live-dot.pulse`). 문구로 설명하지 말 것

## 창 · 상태

- `TICK_WINDOWS = [1, 5, 10, 15, 30, 60, 180]`(분). 자동 갱신 주기는 창에 맞춘다
  (`tickRefreshMs`: 10분 이하 → 10초, 그 위 → 30초). 1분 창은 롤링 값이 1~2칸뿐이라 게이지 위주다
- 창 길이·모드·직접 설정 구간·자동 여부는 `TickProvider` 가 세 화면과 **공유**하고
  (`localStorage["tracex.tick"]`), **뷰 on/off 만 화면별**이다
  (`useTickView(key)` → `localStorage["tracex.tick.view.<key>"]`)
- `TickProvider.persist` 는 **`selRef` 를 동기적으로 먼저 갱신**한다 — 화면이 창을 고른 직후 곧바로
  `resolve()` 로 조회하는데, `setSel` 만 하면 다음 렌더 전까지 이전 창으로 조회하게 된다
- 조회 시각은 `toLocalSec()`(초 정밀). 분 정밀 + `":00"` 을 쓰면 현재 분이 통째로 잘려 방금 난
  버스트가 안 잡힌다
- 모드는 둘. `live` = 창 길이만큼 "지금까지". `custom` = 고정 구간.
  **`custom` 에서는 자동 갱신을 잠근다**(체크박스 disabled + effect 가드) — 라이브 갱신은 매번
  '지금' 으로 창을 다시 잡아 지정한 구간을 덮어쓴다
- 서버는 24시간(`TICK_MAX_MINUTES`)을 넘는 구간을 **뒤쪽(최신)만 남기고** 자른다. 요청한 `from`
  보다 응답 `range.from` 이 뒤면 `clamped` 로 화면이 밝힌다(안 밝히면 잘려나간 앞 구간이
  "그 시간엔 호출이 없었다" 로 오독된다)

## 본문 — `TickMonitor` / `TickMonitorChart`

위에서 아래로 **세 가지만** 답한다: ① 게이지 2장(A/B: 값 + 한도가 있으면 대비 막대·%)
② 추이 차트 ③ 순간 목록.

- **정각 분 합계(`fixed*`)는 그리지 않는다.** 판정값과 비판정값을 나란히 두면 어느 게 기준인지
  헷갈린다. 차트는 롤링 60초 값 하나만 Area 로, 한도는 점선 하나, 초과한 분만 점.
  (`fixed*` 는 응답에 남아 있다 — 같은 쿼리에서 공짜로 나오고 진단에 쓸 수 있어서)
- **A/B 전환은 게이지 카드 클릭이다.** 별도 토글 + KPI 카드를 두면 같은 수치가 두 번 나온다
- **순간 목록은 한도 유무로 갈린다**: 한도가 있으면 "초과한 순간"(연속 초과 분을 구간으로 병합),
  없으면 "가장 몰린 순간"(값 상위 TOP 5). 후자는 같은 버스트의 이웃 분이 목록을 채우지 않도록
  이미 고른 순간과 60초 안에서 겹치는 후보를 건너뛰고, **빨간색을 쓰지 않는다**
  (`.tick-seg-item.neutral` — 초과가 아닌 정상값을 사고로 읽게 된다)
- 행을 열면 그 피크 60초의 원본 행이 나온다 — LLM 소스는 호출 표(`TickCall`), BIZ 소스는 요청 표
  (`TickTrace`). **하나의 범용 표로 합치지 않았다**(열이 겹치지 않아 빈 칸투성이가 된다)
- 시각은 `windowLabel()` 로 `09:16:30 ~ 09:17:30` 처럼 끝 시각을 직접 적는다. 차트 툴팁은 이 구간을
  제목으로 올린다. **화면 문구는 값이 무엇인지 설명하려 들지 말고 숫자·시각·%만 보여줄 것**
- 조회 툴바는 `TickMonitor` 안에 없다 — 페이지 헤더의 `TickPresets`/`TickActions` 가 담당한다
